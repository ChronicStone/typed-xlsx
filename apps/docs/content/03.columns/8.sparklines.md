---
title: Sparklines
description: Add native Excel sparkline columns from typed source columns, groups, or dynamic scopes.
---

Use `sparkline` when a column should render a native Excel mini chart for each row.

The sparkline target can be a sparkline-only column, or it can share a cell with a normal `accessor` or `formula` value.

## Basic usage

```ts twoslash
import { createExcelSchema } from "typed-xlsx";

type Row = {
  account: string;
  jan: number;
  feb: number;
  mar: number;
};

const schema = createExcelSchema<Row>()
  .column("account", { accessor: "account" })
  .column("jan", { accessor: "jan" })
  .column("feb", { accessor: "feb" })
  .column("mar", { accessor: "mar" })
  .column("trend", {
    header: "Trend",
    width: 18,
    sparkline: {
      source: ["jan", "feb", "mar"],
      type: "line",
      emptyCells: "zero",
      style: {
        line: { color: "#2563EB", weight: 1.25 },
        dots: false,
        high: { color: "#16A34A" },
        low: { color: "#DC2626" },
      },
    },
  })
  .build();
```

The source column IDs are checked by TypeScript. A sparkline can only reference columns declared before the sparkline column.

## Source forms

Use an explicit list when you want exact columns:

```ts twoslash
import type { SparklineInput } from "typed-xlsx";

const explicitSource = {
  source: ["jan", "feb", "mar"],
} satisfies SparklineInput<"jan" | "feb" | "mar">;
```

Use a range when the source columns are contiguous:

```ts twoslash
import type { SparklineInput } from "typed-xlsx";

const rangeSource = {
  source: { from: "jan", to: "mar" },
} satisfies SparklineInput<"jan" | "feb" | "mar">;
```

Use a group or dynamic scope when the columns are produced structurally:

```ts twoslash
import type { SparklineInput } from "typed-xlsx";

const groupSource = {
  source: { group: "months" },
} satisfies SparklineInput<string, "months">;
```

```ts twoslash
import type { SparklineInput } from "typed-xlsx";

const dynamicSource = {
  source: { dynamic: "months" },
} satisfies SparklineInput<string, never, "months">;
```

At export time, selected columns must still resolve to a non-empty contiguous range. If a source column is excluded by `select`, typed-xlsx throws a clear error instead of emitting a broken workbook.

## Styling and themes

Sparkline colors come from the active spreadsheet theme by default. A table theme or schema theme can provide these tokens:

- `sparklineSeries`
- `sparklineMarkers`
- `sparklineFirst`
- `sparklineLast`
- `sparklineHigh`
- `sparklineLow`
- `sparklineNegative`
- `sparklineAxis`

Column-level `style` options override the theme:

```ts twoslash
import { createExcelSchema } from "typed-xlsx";

const schema = createExcelSchema<{ jan: number; feb: number; mar: number }>()
  .column("jan", { accessor: "jan" })
  .column("feb", { accessor: "feb" })
  .column("mar", { accessor: "mar" })
  .column("trend", {
    sparkline: {
      source: { from: "jan", to: "mar" },
      style: {
        line: { color: "#2563EB", weight: 1.25 },
        dots: { visible: true, color: "#1D4ED8" },
        first: { color: "#64748B" },
        last: { color: "#10B981" },
        high: { color: "#16A34A" },
        low: { color: "#DC2626" },
        axis: {
          visible: true,
          color: "#94A3B8",
          min: { value: 0 },
          max: "group",
        },
      },
    },
  })
  .build();
```

For column and win/loss sparklines, use `style.series` for the main bar color and `style.negative` for negative values:

```ts twoslash
import { createExcelSchema } from "typed-xlsx";

const schema = createExcelSchema<{ won: number; lost: number; open: number }>()
  .column("won", { accessor: "won" })
  .column("lost", { accessor: "lost" })
  .column("open", { accessor: "open" })
  .column("mix", {
    sparkline: {
      source: ["won", "lost", "open"],
      type: "winLoss",
      style: {
        series: "#16A34A",
        negative: { color: "#DC2626" },
        axis: { visible: true, color: "#64748B" },
      },
    },
  })
  .build();
```

## Supported options

- `type: "line" | "column" | "winLoss"`
- `emptyCells: "gap" | "zero" | "span"`
- `style.series`
- `style.line.color`
- `style.line.weight`
- `style.markers` or `style.dots`
- `style.first`
- `style.last`
- `style.high`
- `style.low`
- `style.negative`
- `style.axis`
- `style.axis.min`
- `style.axis.max`
- `style.hidden`
- `style.rightToLeft`
- `show.markers`
- `show.first`
- `show.last`
- `show.high`
- `show.low`
- `show.negative`
- `show.axis`
- `show.hidden`
- `lineWeight`
- `minAxisType`
- `maxAxisType`
- `manualMin`
- `manualMax`
- `rightToLeft`

`style.markers`, `style.dots`, `style.first`, `style.last`, `style.high`, `style.low`, and `style.negative` accept either a boolean or `{ visible?: boolean; color?: string }`.

`style.axis` accepts either a boolean or `{ visible?: boolean; color?: string; min?: SparklineAxisBound; max?: SparklineAxisBound }`. Axis bounds can be `"individual"`, `"group"`, `"custom"`, or `{ type?: "individual" | "group" | "custom"; value?: number }`.

The lower-level `show`, `colors`, `lineWeight`, `minAxisType`, `maxAxisType`, `manualMin`, `manualMax`, and `rightToLeft` fields remain supported for compatibility. When both are present, `style` wins.
