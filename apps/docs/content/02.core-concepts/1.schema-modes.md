Every schema has a mode, and it decides what the data becomes in Excel:

- **report** (the default) writes a laid-out range: a title, grouped headers, sub-row expansion, summary rows below the data
- **excel-table** writes a native Excel table: filter buttons, banded rows, a totals row, structured references

```ts twoslash
import { createExcelSchema } from "typed-xlsx";

type Order = { product: string; qty: number; price: number };

const report = createExcelSchema<Order>();
const table = createExcelSchema<Order>({ mode: "excel-table" });
```

The column API is the same in both modes. Here is one schema written both ways:

## Compare the modes

|                     | report                                            | excel-table                                                          |
| ------------------- | ------------------------------------------------- | -------------------------------------------------------------------- |
| Output              | a plain range                                     | a native Excel table object                                          |
| Rows below the data | [summary rows](/columns/summary-rows), any number | one [totals row](/excel-tables/totals-row)                           |
| Sub-row expansion   | yes                                               | no                                                                   |
| Grouped headers     | yes                                               | groups are allowed, headers stay one row                             |
| Filters             | opt in with `autoFilter`                          | on by default                                                        |
| Formula references  | A1 (`=(B3*C3)`)                                   | structured (`[@Qty]`)                                                |
| Look                | cell styles and [themes](/styling/themes)         | an Excel [table style](/excel-tables/table-styles), plus cell styles |
| Streaming           | yes                                               | yes                                                                  |

## Which one to pick

Choose **excel-table** when people will sort, filter or pivot the data in Excel, or feed it to Power Query. The table keeps working as they add rows.

Choose **report** when the sheet is something people read: it needs a title, several summary lines, or line items expanded under their parent record.

## Same formulas, different output

You write formulas once with `refs.column()`. The mode decides how they are written into the file:

```ts twoslash
import { createExcelSchema } from "typed-xlsx";

type Order = { product: string; qty: number; price: number };

const reportSchema = createExcelSchema<Order>()
  .column("qty", { header: "Qty", accessor: "qty" })
  .column("price", { header: "Price", accessor: "price" })
  .column("total", {
    header: "Total",
    formula: ({ refs }) => refs.column("qty").mul(refs.column("price")),
  })
  .build();

const tableSchema = createExcelSchema<Order>({ mode: "excel-table" })
  .column("qty", { header: "Qty", accessor: "qty" })
  .column("price", { header: "Price", accessor: "price" })
  .column("total", {
    header: "Total",
    formula: ({ refs }) => refs.column("qty").mul(refs.column("price")),
  })
  .build();
```

In report mode the cell holds `=(A2*B2)`. In excel-table mode it holds a structured reference to the same row, which Excel displays as `=([@Qty]*[@Price])` and keeps correct when someone sorts or inserts rows.

## Mode and builder are separate choices

The mode decides what the data looks like. The builder, `createWorkbook()` or `createWorkbookStream()`, decides how rows reach the file. All four combinations work. See [Execution Model](/core-concepts/execution-model).
